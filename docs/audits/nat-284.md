# NAT-284 pre-release audit

Audited `main` at `722fd46c86bf4675ee124c0df273e9866d497a02` on November 13, 2026. The issue branch changes OTP delivery and adds this report. Other fixes belong to the linked follow-ups.

**The current tree is not release-ready.** The web production build fails, and live collaboration leaks new source updates to removed collaborators. The audit is complete; closing the audit does not close the release findings.

## Changes made in this issue

`apps/app/src/lib/auth.ts` now sends sign-in, email-verification and password-reset codes through the existing email service. It also handles the installed plugin's email-change variant without enabling that feature. Each email has purpose-specific text and HTML, and the plugin explicitly uses the advertised five-minute lifetime.

`apps/app/src/lib/email.ts` now lets provider errors reach Better Auth rather than swallowing them. Better Auth intentionally reports OTP callback failures through its logger and returns a generic response. This change does not promise that the public endpoint reveals a delivery failure.

Five tests in `auth-otp.test.ts` exercise the installed Better Auth plugin with its real memory adapter and a captured mail transport. They cover successful sign-in and verified sessions, existing-account verification, password reset followed by login with the new password, rejection of the old password, invalid codes, consumed codes, expiry, email contents, and delivery callback failures. These tests do not send external email.

The issues contain reproduction steps, source locations, test gaps and acceptance criteria. NAT-297, NAT-298 and NAT-299 are children of the UI overhaul, NAT-286. Functional backend findings are children of this audit.

### Highest-risk findings

- **NAT-290:** In the real collaboration runtime, removing a collaborator's SQL membership did not stop new source updates reaching their existing socket. Access checks guard incoming messages, but `broadcast` delivers to all tagged sockets. Compile SSE has the same attachment-only authorization concern by source inspection; that SSE case was not separately reproduced.
- **NAT-291:** After saving, deleting a project and collecting its real R2 sources, a nonempty clean Yjs snapshot remained in collaboration SQLite. Only dirty documents reach the flush cleanup path, so clean idle documents lack a purge path.
- **NAT-289:** `bun run --cwd apps/app build` fails because `styles.css:5` imports `@fontsource-variable/geist` without a manifest or lockfile dependency. CI runs no production build.
- **NAT-292:** Binary upload acknowledgement does not update the editor's source-version map. The next compile fails with `Save image.png before compiling`; reopening the project supplies the missing hash.
- **NAT-300:** The production CAPTCHA configuration rejects tokenless sign-in OTP requests but allows the reset-specific endpoint to send email without a token. Better Auth's other rate limits still apply.

### Other reproduced integration gaps

- **NAT-293:** A collaborator can read a personal project by ID, but `getProjects` excludes it from their dashboard.
- **NAT-294:** A soft-deleted personal project still reserves its owner's project name through an unconditional unique index.
- **NAT-295:** The web validator accepts `chapter:1.tex` and a 241-character filename; the compiler rejects the entire project containing either path. Nested full-path lengths are not checked at creation.
- **NAT-296:** File metadata has initial route snapshots and local RPC acknowledgements only. Another open collection never learns about a new file. The text CRDT protocol and build SSE do not carry node metadata.
- **NAT-301:** The actual authenticated compile handler returns 202 once, then throws a Postgres duplicate-key error on an identical compilation-ID retry. The compiler's idempotency checks sit below this failing boundary.

The binary probe ran the real files store with a captured server acknowledgement and executed the original `sourceFiles` function extracted from the workspace. The metadata probe ran two real RPC collections with a shared server fixture. Neither was a full rendered-workspace browser test. The compile-route probe used the real handler and Postgres, with fixtures for session identity and the compiler response. The CAPTCHA probe used the production plugin configuration and real Better Auth HTTP handling, with memory storage and a captured sender.
